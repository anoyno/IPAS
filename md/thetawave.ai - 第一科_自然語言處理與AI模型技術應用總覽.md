## 🧠 自然語言處理（NLP）與情感分析

> **情感分析（Sentiment Analysis）**：判斷文本中所表達的**情感傾向**，例如正面、負面或中性，是企業了解顧客滿意度的關鍵技術。

- 目的：分析顧客在社群平台和商品評論中的文字內容，**即時掌握顧客情感變化**。
- 常見誤解：情感分析不涉及語言風格預測、自動翻譯或摘要生成。

## 🔄 Transformer 架構與自注意力機制

> Transformer模型能顯著提升長文本翻譯品質，主要是因為其**自注意力機制（Self-Attention Mechanism）**，可捕捉長距離語境依賴關係。

- 自注意力機制：讓模型在處理序列時，能同時關注序列中不同位置的資訊，擺脫傳統RNN只能線性處理的限制。
- 不同於卷積運算或強化學習，Transformer專注於上下文的全面理解。

## 🤖 BERT模型與遮罩語言模型（MLM）

> BERT模型的預訓練策略為**遮罩語言模型（Masked Language Model, MLM）**，透過隨機遮罩部分詞語，讓模型根據**雙向上下文（Bidirectional Context）**預測被遮罩的詞。

- 不同於單向語言模型，BERT同時考慮詞語前後的上下文資訊，提升語言理解能力。
- 對抗訓練與解碼器結構並非MLM的核心訓練方法。

## 📚 詞向量訓練方法：Word2Vec vs GloVe

| 特色 | Word2Vec | GloVe (Global Vectors) |
| --- | --- | --- |
| 類型 | 基於預測的模型（Predictive Model） | 基於共現統計的模型（Statistical Model） |
| 方法 | 利用神經網路預測上下文詞語 | 利用詞共現矩陣的全局統計信息 |
| 應用 | 靜態詞向量 | 靜態詞向量，較適合全局語料分析 |

## 🔢 TF-IDF方法與長文本問題

> TF-IDF（詞頻–逆文件頻率）在長文本中可能失效，主要因為**長文本使詞頻偏高，導致常見詞權重被過度放大**，影響關鍵詞重要性的準確反映。

- TF-IDF無法有效區分長文本中詞語的重要性，尤其是常見詞的詞頻膨脹。

## 🗣️ N-gram語言模型限制

> N-gram模型的主要限制在於**僅依賴固定長度的前序詞進行機率估計，難以捕捉長距離依賴關係（Long-range Dependencies）**。

- 導致生成句子片段合理，但缺乏整體語意連貫。
- 無法處理語意嵌入，且假設詞與詞之間相互獨立。

## 🎯 物件偵測與評估指標

| 指標 | 說明 | 影響 |
| --- | --- | --- |
| IoU（Intersection over Union） | 預測邊界框與真實邊界框的重疊比例 | 閾值越高，要求模型預測框與真實框重疊程度越高，評估更嚴格。 |
| mAP（Mean Average Precision） | 平均精確率，是多類別物件偵測的整體評估指標 | 反映模型在不同IoU閾值下的偵測準確性。 |

- IoU閾值設定較高代表**模型偵測結果更精準**。

## 🔢 Softmax 與 Max-Pooling 的差異

| 特性 | Softmax | Max-Pooling |
| --- | --- | --- |
| 功能 | 將特徵張量轉換為機率分佈，保留所有輸入資訊，以比例表示 | 僅保留區域最大值，進行特徵降維 |
| 用途 | 分類問題中常用於輸出機率分佈 | 特徵降維與縮減空間維度 |

## 📈 資料增強（Data Augmentation）與模型效能

> 資料增強若導致模型效能下降，最可能原因是**增強後資料的特徵分佈與原始資料不一致，影響模型的泛化能力**。

- 改善策略：調整增強策略，確保語意一致性以維持資料分佈相似。

## 🎯 精確率、召回率與綜合評估指標

| 指標 | 說明 | 適用情境 |
| --- | --- | --- |
| 精確率（Precision） | 正確預測為正例的比例 | 強調預測結果的準確性 |
| 召回率（Recall） | 真正正例被正確檢出的比例 | 強調預測結果的全面性 |
| F1 分數（F1 Score） | 精確率與召回率的調和平均，兼顧兩者的綜合指標 | 同時需要兼顧精確率與召回率的場合 |

- 若希望同時兼顧精確率和召回率，**使用F1分數作為綜合評估標準**。

## 🔍 DBSCAN演算法超參數

| 超參數 | 說明 |
| --- | --- |
| 鄰域半徑（Epsilon, ε） | 決定資料點被視為鄰居的距離範圍 |
| 最小點數（MinPts） | 定義核心點所需的最低鄰居數量 |

- 這兩個超參數決定聚類結果，可自動區分主要群集與雜訊資料。

## 📊 線性迴歸中的多重共線性問題與解決方案

> 多重共線性會導致模型係數不穩定、預測誤差升高，解決方法為**使用主成分分析（PCA）將相關特徵轉換為彼此獨立的主成分**。

- PCA能降低特徵間的相關性，提升模型穩定度與泛化能力。

## ☸ Kubernetes在AI模型部署核心功能

> Kubernetes主要負責**管理與協調模型服務的部署、擴展與運行環境**，確保模型在生產環境中的高可用性與彈性。

- 不直接管理模型訓練或資料版本控管。
- 支援容器化與自動擴展。

## ⚙️ 超參數調整與過擬合防止策略

| 方法 | 說明 |
| --- | --- |
| 交叉驗證（Cross-Validation） | 在多組參數組合間反覆評估，選擇在驗證資料上表現最穩定的設定。 |
| 早期停止（Early Stopping） | 監控訓練誤差，訓練過程中提前停止以防過擬合。 |

- 交叉驗證是最有效提升模型泛化能力的方法。

## 🗃️ MLOps流程中的Model Registry功能

> Model Registry用於**集中管理模型版本、訓練紀錄與部署狀態**，方便模型的追蹤與管理。

- 不是用於設定運算資源或資料版本控管。

## 🔄 序列到序列（Seq2Seq）模型適用場景

| 任務類型 | 適用性 |
| --- | --- |
| 自動翻譯 | 適合，將輸入文字轉換成語意等價另一段文字 |
| 摘要生成 | 適合，生成語意等價的摘要文本 |
| 預測數值序列 | 不適合，屬於時間序列分析 |
| 命名實體識別 | 不適合，屬於序列標註任務 |

- Seq2Seq模型專注於**輸入序列映射到輸出序列**，適合翻譯、摘要等任務。

## ⚙️ 檢索增強生成（RAG）系統挑戰

> RAG系統在檢索階段最關鍵的挑戰是**避免向量檢索結果僅具語意相似但與查詢意圖無實質關聯**。

- 即使向量相似，仍需確保檢索內容與用戶查詢目標高度相關，減少幻覺（Hallucination）現象。

## ⚡ Transformer注意力分布問題與改善方法

> 當Transformer模型發生**注意力分布過於平均（Attention Collapse）**，導致無法聚焦關鍵資訊時，應對注意力權重施加**稀疏化約束（Sparsity Constraint）**以改善。

- 其他方法如加入高斯噪音或使用ReLU取代Softmax效果差。

## 🗣️ 低資源語言模型過擬合與改進策略

> 在低資源語言（語料量少）訓練中，提升泛化能力的有效方法是**採用反向翻譯（Back-Translation）生成偽平行語料（Pseudo-Parallel Corpus）**。

- 透過資料增強產生更多訓練資料，避免模型過擬合。
- 凍結預訓練模型層也能保留知識，但不如反向翻譯效果顯著。

## ⚔️ 生成對抗網路（GAN）的模式崩潰問題解決

> 為解決GAN中的**模式崩潰（Mode Collapse）問題，最常用的方法是採用Wasserstein距離（WGAN損失）替代原始GAN損失函數**。

- WGAN能提供更穩定的訓練動態，促進多樣性。
- 其他方法如梯度懲罰、隨機擾動或多尺度鑑別器輔助效果有限。

## 🖼️ 多模態AI模型缺失模態處理策略

> 面對某模態資料缺失，最有效策略是**訓練具備模態缺失感知能力的模型**，使其能適應缺失狀況，維持模型效能。

- 簡單填充零向量或捨棄樣本效果較差。
- 利用生成模型補全模態需謹慎，避免引入假資訊。

## 🔄 資料漂移（Data Drift）偵測方法

| 方法 | 說明 |
| --- | --- |
| KL 散度（KL Divergence） | 計算輸入特徵分佈與原始訓練資料分布差異，偵測資料分佈變化。 |
| 重新訓練模型 | 是應對資料漂移的措施，但非偵測方法。 |

- 計算KL散度是偵測資料分布變化的合適方法。

## 🚦 漸進式部署（Phased Rollout）策略

> 為降低對臨床流程衝擊並控制風險，應採取**從單一專科或特定病房開始啟用，逐步擴展至全院**的漸進式部署策略。

- 有利於風險管控與回饋收斂。
- 其他選項如急診或夜班部署缺乏全面性。

## 🛡️ AI風控系統對抗性攻擊防禦

| 防禦措施 | 是否適用於對抗性攻擊防禦 |
| --- | --- |
| 強化資料前處理 | 適用，過濾異常輸入 |
| 對抗樣本訓練 | 適用，提升模型對惡意擾動辨識能力 |
| 規則引擎後處理 | 適用，確保結果符合業務規則 |
| 強化網路防火牆 | 不適用，防火牆非模型本身防禦手段 |

- 強化網路防火牆屬於系統層面防護，不是針對模型本體的對抗性防禦。

## ⚖️ 生成式AI系統法律風險防範

> 最有效預防著作權侵權問題的是**建立訓練資料篩選與授權驗證機制，排除未授權或高風險資料來源**。

- 其他方法如語意相似度標註、差分隱私、浮水印有輔助作用，但無法完全杜絕侵權。

## 📉 多重共線性問題與迴歸模型選擇

| 模型類型 | 對多重共線性的影響 |
| --- | --- |
| 傳統線性迴歸（無正則化） | 受多重共線性影響，係數不穩定 |
| 決策樹模型 | 不受多重共線性影響 |
| LASSO迴歸（含L1正則化） | 可降低共線性影響，進行特徵選擇與縮減 |

- 針對線性迴歸，**含L1正則化的LASSO迴歸模型**為降低共線性影響的優選。

## 📝 半結構化資料特徵抽取策略

> 面對含巢狀欄位的JSON格式半結構化資料，最有效且實務可行的策略是**設計遞迴函式展開巢狀欄位，並基於時間窗口進行聚合與特徵萃取**。

- 直接扁平化成CSV並計算統計量可能丟失時序資訊。
- 使用RNN直接輸入JSON字串不實務。

## 🔧 混合型特徵工程方法

| 特徵類型 | 建議處理方法 |
| --- | --- |
| 連續特徵 | 標準化（Standardization） |
| 類別特徵 | 目標編碼（Target Encoding） |
| 交互特徵 | 生成以提升模型表現 |

- 對連續與類別特徵分別採用適合的編碼與標準化方法，提升整體模型效能。

## 🔄 持續整合（Continuous Integration, CI）核心實踐

> CI的核心是**每次程式碼提交後自動觸發建置、單元測試及靜態程式碼分析**，減少整合風險。

- 不建議每日手動合併或定期回顧合併。
- 自動化流程能即時發現問題。

## 🔐 AI系統不可否認性保證

> 為確保不可否認性，應對每筆模型推論記錄的輸入與輸出結果產生**加密雜湊值（Hash）並簽署數位簽章**，防止資料被竄改。

- 不應只優化效能或增加主機備援。

## 🚀 高可用性AI服務架構

> 支援高流量（如10,000 RPS）的AI服務，應採用**容器化部署並水平擴展服務實例，結合自動彈性伸縮機制（Auto Scaling）**。

- 單台垂直擴展無法應對流量峰值。
- 控制併發連線或增加批次處理不利於低延遲需求。

## 📉 模型效能預警指標

| 監控指標 | 預警效力 |
| --- | --- |
| PSI（Population Stability Index） | 輸入特徵與訓練資料分布差異，提早發現模型效能下滑風險。 |

- CPU、記憶體使用率或置信度分佈較少用於預測模型效能衰退。

## 🧩 Word2Vec模型訓練策略

> 若需更有效捕捉罕見詞的語意關聯，建議採用**Skip-gram模型，利用中心詞預測周圍詞語**，特別適合低頻詞學習。

- CBOW模型較適合高頻詞穩定表示。

## 🚗 電腦視覺技術分類

| 技術名稱 | 功能說明 |
| --- | --- |
| 語義分割（Semantic Segmentation） | 區分不同物件類別，但不區分個體 |
| 物件偵測（Object Detection） | 辨識物件存在位置與框出邊界 |
| 實例分割（Instance Segmentation） | 區分同類物件的不同個體 |
| 全景分割（Panoptic Segmentation） | 結合語義分割與實例分割，全面標註每個像素屬性及個體身份 |

- 若需辨識物件類別及區分個體，應採用**實例分割**技術。

## 🖼️ CLIP模型關鍵技術特性

> CLIP模型透過**圖文對比式學習（Contrastive Learning）將影像與文字映射至共享嵌入空間（Shared Embedding Space），支持零樣本分類（Zero-shot Classification）**。

- 無需新增標註資料，只需文字提示即可搜尋與識別影像內容。

## 🔍 模型超參數系統化搜尋方法

| 方法 | 特點及用途 |
| --- | --- |
| 交叉驗證 | 評估模型泛化能力，降低過擬合風險 |
| 網格搜尋（Grid Search） | 系統化遍歷多組超參數組合，找出最佳組合 |
| 隨機搜尋 | 快速探索部分參數空間，提高搜尋效率 |
| 貝葉斯優化 | 根據歷次結果動態調整搜尋方向，提升搜尋效果 |

- 若目標是系統化找出驗證資料上最穩定的組合，**網格搜尋**為常用方法。

## 💾 GPU記憶體不足解決方案

> 在模型架構固定且無法換硬體情況下，**減少單張GPU的記憶體壓力**通常透過調整批次大小、使用混合精度訓練或模型切片等技術。

- 文字稿未完整提供訓練策略細節，僅提示需要降低單GPU記憶體壓力。

### 🔍 影像生成與品質提升

> **Stable Diffusion** 在生成高解析度（如4K）影像時，常見邊緣顆粒化與模糊問題。  
> 為提升畫面清晰度與紋理層次，且避免過度平滑，最佳策略是：

| 選項 | 作法說明 | 適用性說明 |
| --- | --- | --- |
| (A) | 降低取樣步數以縮短生成時間 | 可能降低細節還原度，畫質變差 |
| (B) | 增加取樣步數並選擇高品質取樣器 | **強化細節還原與畫質穩定性，是最佳選擇** |
| (C) | 提高CFG（Classifier-Free Guidance）值 | 增強創意與多樣性，非針對清晰度調整 |
| (D) | 改用低解析度輸入以降低計算成本 | 反而降低最終解析度，影響細節呈現 |

### 📈 時間序列模型診斷：ARIMA模型

> ARIMA（自回歸整合移動平均模型）用於時間序列預測時，殘差分析是判斷模型適配度的重要方法。  
> 若殘差呈現週期性波動，且自相關函數（ACF）在多個時滯顯著不為零，代表：

| 選項 | 診斷結果 | 解釋 |
| --- | --- | --- |
| (A) | 殘差符合白噪音假設，預測穩定 | 不符，因殘差仍有顯著自相關，非白噪音 |
| (B) | 殘差異常輕微，可忽略 | 不符，殘差週期且顯著，不能忽略 |
| (C) | **模型配適不足（Underfitting），需調整p或q參數** | **模型未捕捉時間依賴性，需重新設定自回歸或移動平均階數** |
| (D) | 殘差特性不影響預測 | 不符，需修正以改善預測 |

### 🧠 生成模型差異：VAE、GAN與擴散模型

> 生成模型在多模態潛在空間對齊與生成策略上有根本差異：

| 模型 | 潛在空間對齊方式 | 生成策略 | 特點說明 |
| --- | --- | --- | --- |
| **VAE（變分自編碼器）** | 透過顯式潛在變數建模，捕捉整體語意結構 | 透過變分推斷重建樣本 | 適合語意結構捕捉，但生成解析度有限 |
| **GAN（生成對抗網路）** | 對抗損失學習不同模態分佈映射 | 對抗式訓練生成高解析度樣本 | 生成品質高但訓練不穩定 |
| **擴散模型（Diffusion Model）** | 條件化噪聲反推，實現跨模態高保真生成 | 透過逐步去噪生成高質量樣本 | 兼具穩定性與多樣性 |

> **正確選項為 (A)**，描述了三者在潛在空間對齊與生成策略的根本差異。

### ⚙️ 超參數調校與交叉驗證問題

> 在 K-Fold 交叉驗證中，若直接在驗證資料上調整模型參數並評估效能，會產生：

| 問題類型 | 說明 |
| --- | --- |
| **過度樂觀偏差（Over-optimistic Bias）** | 測試摺資料間接參與參數選擇，造成資料洩漏，導致效能評估偏高 |
| 過度正則化或訓練不穩定 | 反覆調整參數可能引起 |
| 效能方差增大 | 重複使用資料可能導致 |
| 驗證過程失效 | 假設與搜尋不相容 |

> **重點：資料洩漏是主要風險，導致交叉驗證結果過度樂觀。**  
> 正確答案為 (A)。

### 🔄 模型部署與資料分布偏移對策

> 當深度學習模型（如 Transformer 分類器）部署後，因輸入資料分布變化導致性能下降，應用下列策略：

| 選項 | 說明 |
| --- | --- |
| (A) 生成對抗網路生成新樣本混入訓練集 | 雖可增加資料多樣性，但非直接監控資料偏移 |
| (B) 改用邏輯迴歸提升穩定性 | 可能犧牲模型表現，非最佳策略 |
| (C) 增加模型容量學習更多樣本差異 | 容量大不一定解決資料偏移問題 |
| (D) **使用變分自編碼器（VAE）監控潛在空間分布，偵測資料偏移** | **可即時偵測並反應資料分布變化，為最佳策略** |

### 🧪 AI模型資料利用效率比較：生成式 vs 鑑別式

| 路徑 | 模型範例 | 特點 | 適合比較方法 |
| --- | --- | --- | --- |
| 生成式路徑 | VAE | 利用潛在語意空間建模，較適合低資源情境 | 在低資源設定下，逐步減少標註資料比例，觀察F1-score變化 |
| 鑑別式路徑 | BERT Classifier | 直接監督式分類，資料利用效率較低 | 同上 |

> **最佳設計為** (B) 在低資源環境逐步減少標註資料，觀察兩模型泛化能力差異。

### 💡 多任務學習中任務間競爭問題

> 單一 Transformer 模型同時執行OCR與命名實體辨識（NER）時，若NER準確率提升導致文檔分類準確率下降，常見原因為：

| 原因 | 說明 |
| --- | --- |
| 模型架構無法支援多任務 | 不符，Transformer支援多任務輸出頭 |
| 文檔分類不需語意化表徵 | 不符，語意化表徵對分類重要 |
| **損失函數未平衡，任務間競爭** | **未調整損失權重，導致部分任務損失主導訓練** |
| 模型無法多任務輸出 | 不符，BERT具多任務輸出能力 |

### 🚀 高維資料聚類效能提升策略

> 使用 DBSCAN 演算法處理數百萬筆高維資料時，遇記憶體不足與運算緩慢問題，合理解決方案：

| 選項 | 說明 |
| --- | --- |
| 改用階層式群集法 | 非DBSCAN，改變演算法核心不符題意 |
| **採用高效率距離索引結構（KD-Tree 或 Ball Tree）** | **加速鄰近點搜尋，提升DBSCAN效率，符合要求** |
| 將 ε 參數調得極小 | 反而增加群集數量，效率不見得提升 |
| 增加標準化後特徵維度數 | 維度增多反而加劇計算負擔 |

### 📉 主成分分析（PCA）與支持向量機（SVM）

| 描述 | 合理性說明 |
| --- | --- |
| PCA必然提升SVM分類準確率 | 錯誤，PCA降維可能丟失資訊，非必然提升準確率 |
| 使用原始高維資料保留資訊較多 | 部分正確，但高維資料可能導致過擬合與計算負擔 |
| PCA使SVM自動適用非線性資料集 | 錯誤，PCA是線性降維，無法自動解決非線性問題 |
| **降維後降低訓練時間並減少過擬合風險** | **合理，降維減少特徵數，有助於提升訓練效率與避免過擬合** |

### ⚠️ MLOps中資料與概念漂移監控

> 為主動偵測模型輸入資料分布偏移，應採用：

| 措施 | 功能說明 |
| --- | --- |
| **建立即時資料漂移與概念漂移監測機制** | 即時監控輸入資料分布與標籤關係變化，預警模型性能下降 |
| 轉換模型為量化版本 | 降低延遲，不解決資料偏移問題 |
| 增加超參數調整次數 | 不能主動偵測漂移 |
| 使用固定隨機種子 | 保證訓練穩定，非漂移監控 |

### 🤖 多模態生成模型技術機制問題分析

> 在多模態生成（如文字+影像）中，提示語生成的圖像中品牌標誌顏色錯誤或人物手部不自然，最可能原因：

| 選項 | 技術解釋 |
| --- | --- |
| 擴散模型去雜訊過程出現梯度漂移 | 可能影響像素，但不直接導致語意理解錯誤 |
| 提示語過長導致位置編碼限制 | 長提示會影響生成，但非主要原因 |
| **CLIP模型中文本與影像編碼器語意嵌入空間未充分對齊** | **跨模態語意理解偏差，導致生成細節錯誤，是根本原因** |
| 未採用對比學習損失函數 | 雖影響語意關聯，但CLIP已採用對比學習，非缺失現象 |
